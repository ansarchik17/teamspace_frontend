# UniteSpace на своём Mac

Этот профиль публикует собранный основной портал и Go API на
`https://unitespace.kz/web/`. VPS не нужен. Mac, Docker Desktop и интернет
должны работать всё время. Закрытая крышка, перезагрузка или смена сети могут
остановить доступ. Профиль не запускает отдельные приложения AI, почты,
ЭДО и другие внешние интеграции, для которых нужны собственные сервисы.
Keycloak используется API локально, его административная консоль не публикуется.
Вход по логину/паролю и приглашения не требуют публичной консоли Keycloak;
внешние OAuth/SSO-переходы потребуют отдельной настройки публичного Keycloak.

## 1. Проверить домашний интернет

Откройте настройки своего роутера и найдите WAN / Internet IPv4. Сравните его
с внешним IPv4, который показывает `curl -4 https://api.ipify.org` на Mac.
Адреса должны совпадать для прямого проброса через единственный роутер.
WAN в диапазонах `10.x`, `192.168.x`, `172.16–31.x` или `100.64–127.x`
означает дополнительный NAT. Нужно выяснить у провайдера возможность входящих
подключений / публичного IPv4 или настроить вышестоящий собственный роутер.
Публичный IP не обязательно статический, но при его смене придётся обновлять DNS.
Размещение Mac должно соответствовать требованиям домена `.kz`.

## 2. Настроить DNS в Hoster.kz

В личном кабинете выберите **Домены → unitespace.kz**. Для DNS-хостинга Hoster
использует `ns1.hoster.kz`, `ns2.hoster.kz`, `ns3.hoster.kz`. Включите DNS-хостинг,
если он ещё не активен, и настройте A-запись основного домена на подтверждённый
внешний IPv4 вашей сети. В профиле используется только основной домен:
`www` и поддомены компаний отдельно не публикуются. Удалять почтовые MX/TXT
записи не нужно. Не оставляйте AAAA, ведущую на другой сервер.

Проверьте публикацию: `dig +short A unitespace.kz`. Пустой ответ или NXDOMAIN
после регистрации требует проверки делегирования/активации DNS у регистратора.
Распространение изменений занимает время.

## 3. Подготовить Mac и роутер

Установите Caddy: `brew install caddy`.
Закрепите текущий LAN IPv4 Mac через DHCP reservation на своём роутере.
Добавьте **только два** правила перенаправления:

| Внешний порт | Адрес Mac в домашней сети | Порт на Mac | Протокол |
|---|---|---|---|
| 80 | Закреплённый LAN IPv4 Mac | 9080 | TCP |
| 443 | Закреплённый LAN IPv4 Mac | 9443 | TCP |

Если macOS спрашивает о сетевом доступе Caddy, разрешите входящие подключения
для этого приложения. Административная панель роутера не должна занимать
внешние 80/443. Порты PostgreSQL, Redis, MinIO, Keycloak, 8080 и Vite 5173
не нужно перенаправлять. HTTPS-прокси обращается к ним локально.

## 4. Проверить без публикации

При уже работающем обычном backend `npm run dev`:

```bash
npm run host:mac:preview
```

Открывается `http://127.0.0.1:9080/web/`. Команда собирает frontend и раздаёт
`dist` через Caddy, а не через dev-сервер Vite. Она привязана только к loopback,
не обращается за TLS-сертификатом и не меняет DNS/роутер. Ссылки на файлы и
приглашения при таком тесте остаются взятыми из текущей конфигурации backend.
Завершите проверку через Ctrl+C перед публичным запуском.

`npm run test:mac-hosting` проверяет обе конфигурации на изолированных
данных: реальные HTTP/HTTPS-запросы, сертификат локального тестового центра,
редиректы, SPA, закрытые пути, проксирование API и подписанного PUT.
Тест не меняет DNS/роутер и не обращается к рабочей базе или публичному CA.
Нужны Caddy и OpenSSL с поддержкой `-addext`.

## 5. Запустить публичный сайт

В терминале backend:

```bash
npm run dev:infra
# Остановите npm run dev через Ctrl+C в том терминале, где он запущен.
npm run host:mac
```

Backend-команда не меняет `.env`: она выставляет публичный адрес
`https://unitespace.kz`, CORS для домена и localhost и слушает `127.0.0.1:8080`.
Используются текущая база, учётные записи и локальный Keycloak. Этот профиль
рассчитан на локальный bucket `workspace`; подписанные PUT заметок проходят
через тот же домен в MinIO с сохранением Host и пути.

В терминале frontend:

```bash
npm run host:mac
```

Команда проверяет DNS, совпадение A-записи с текущим внешним IPv4, доступность
API и конфигурацию Caddy. Затем собирает frontend с API на своём домене,
отключёнными переходами на поддомены компаний и без старого внешнего почтового
адреса. Caddy получает и обновляет публичный TLS-сертификат. Для выпуска
сертификата должны работать DNS и входящие 80/443. `caffeinate -i` удерживает
Mac от простоя во время работы команды, но не спасает от закрытия крышки,
выключения или потери интернета. Автозапуск после перезагрузки не настроен.

Проверьте `https://unitespace.kz/web/` с телефона **через мобильный интернет**,
не через домашний Wi-Fi: некоторые роутеры не поддерживают NAT loopback.
Проверьте вход, сотрудников, приглашение и загрузку/скачивание файла.
Не начинайте пользоваться чужими реальными аккаунтами для проверки.

Ctrl+C останавливает запущенную команду. Docker-тома и данные сохраняются.
Для возврата к разработке остановите host:mac и запустите привычный npm run dev.
