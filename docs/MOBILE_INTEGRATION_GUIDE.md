# Руководство по интеграции Alem Drive для мобильных приложений

Офисные файлы Alem Drive открываются в Collabora Online внутри WebView. Мобильное приложение открывает страницу Drive; backend запускает Collabora и передаёт ей короткоживущий доступ к одному файлу через WOPI.

## Открытие документа

Открывайте существующий маршрут редактора:

```text
https://[DOMAIN]/drive/editor/[FILE_ID]?embedded=true
```

Параметр `embedded=true` скрывает шапку редактора сайта, чтобы Collabora занимала всё окно WebView. Встроенная страница отправляет пользователя назад средствами приложения.

Если приложение использует передачу access token через URL, используйте текущий механизм авторизации Alem Workspace. Для загрузки launch-страницы и WOPI-сессии WebView должен отправлять авторизационные cookies для домена приложения.

## WebView

- Разрешите JavaScript и cookies для домена приложения.
- Разрешите навигацию во встроенном окне на настроенный домен Collabora.
- Разрешите clipboard read/write для WebView, если платформа предоставляет такую настройку.
- Реализуйте нативную кнопку возврата/закрытия WebView.

## Серверная настройка

Backend должен иметь `COLLABORA_URL`, указывающий на внешний URL Collabora Online, доступный и backend, и браузеру/WebView. Collabora должна быть настроена доверять WOPI-хосту Alem Drive, а reverse proxy должен передавать WebSocket-соединения.

Frontend не загружает `api.js` и не формирует конфигурацию Collabora. Backend получает `/hosting/discovery`, выбирает действие для расширения файла и отправляет форму запуска Collabora. WOPI-токен разрешает доступ только к указанному файлу и истекает через восемь часов.

## Поддерживаемые сценарии

- Office-файлы, открытые из Drive, редактируются согласно правам пользователя.
- Office-файлы по публичной ссылке открываются только для чтения.
- Сохранения Collabora попадают в обычную историю версий Alem Drive.
