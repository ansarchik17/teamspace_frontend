# Управление командой BAS-017

Рабочий кабинет использует существующий WorkspaceLayout: сайдбар, верхняя
панель и оформление других страниц сохраняются. Изменения находятся внутри
раздела «Люди» → «Управление командой» (для платформы — «Компании»).

## Маршруты

- Директор: `/web/organization/administration`.
- Платформа: `/web/platform/administration`.
- Журнал всех компаний: `/web/platform/administration/audit`.
- Компания платформы: `/web/platform/organizations/:organizationId/administration`.
- Вложенные разделы: `/users`, `/modules`, `/storage`, `/integrations`, `/audit`.
- Старый адрес `/web/organization/admin-preview` перенаправляет в рабочий кабинет.

Демонстрационные данные и переключатель роли удалены. Все запросы проходят
через authorizedFetch; сервер определяет права по актуальной БД. Обычный
сотрудник получает отказ, директор работает через current, платформа — через
platform. Формы учитывают capabilities, отправляют revision для модулей и
квот, перечитывают данные после сохранения. При 409 состояние обновляется,
повторное изменение пользователь подтверждает самостоятельно.

## Операции

Обзор и поиск сотрудников, назначение существующей должности, блокировка,
включение разрешённых модулей, персональные квоты Drive и журнал безопасности
с фильтрами подключены к реальному API. Кнопки выгрузки CSV в интерфейсе нет. Структура и права
по должностям открываются в существующих рабочих страницах.

У записей административного аудита есть кнопка «Изменения»: она открывает
сохранённые сервером значения до/после, выделяет изменённые поля и позволяет
показать неизменённые. Запрашивается конкретная запись в разрешённой компании;
если её нет, соседняя запись не подставляется. Секреты дополнительно скрываются.

В разделе «Квоты» рядом с Drive отображается таблица почтовых ящиков AxisMail.
Директор и администратор платформы изменяют почтовые квоты здесь, в общем
интерфейсе управления компанией. Workspace проверяет роль и компанию,
а к AxisMail обращается по внутреннему серверному API. Секрет не попадает в браузер.
Квоты ящиков не могут превышать почтовую долю компании. Снижение ниже занятого
объёма отклоняется. Пока почтовый сервер применяет изменение, AxisMail показывает
ожидание; прежняя квота остаётся зарезервированной до подтверждения снижения.

Платформа дополнительно создаёт и приостанавливает компании, назначает
директора, разрешает модули и задаёт общий бюджет Drive/AxisMail. Перед
изменением бюджета получает допустимый максимум от сервера по данным MinIO.
Нулевые значения сохраняются; null означает отсутствие настроенного бюджета.
Снижение персональной квоты ниже занятого объёма требует подтверждения.

OIDC/SAML доступны только администратору платформы. Директору вкладка не
показывается; бывшие current-маршруты управления возвращают 403. Создание
сохраняет подключение выключенным. Пустой секрет при редактировании сохраняет
существующий. Секреты не отображаются в ответах; полный сценарий внешнего
входа следует проверить после настройки у провайдера, статусы его не заменяют.

## Проверка и выпуск

`npm run build`, `node --test tests/administration-api.test.mjs` и lint; backend тесты административных прав,
квот и OIDC/SAML с отдельной TEST_MESSENGER_DATABASE_URL. Изменения UI следует
выпускать вместе с backend-политикой platform-only для интеграций.
Для редактирования почтовых квот нужно также выпустить обновлённый AxisMail
из deploy/mail/source. Требуются Stalwart и настроенная интеграция общего бюджета.
Иконки модулей соответствуют каталогу сервисов; у Обучения используется иконка выпускника.
