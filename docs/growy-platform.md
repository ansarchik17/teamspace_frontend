# CRM и WhatsApp в Workspace

## Маршруты

- `/web/crm`: лиды, контакты, сделки, задачи и стадии. Поиск, страницы списка, создание и редактирование записей.
- `/web/whatsapp`: диалоги, сообщения, история, статусы доставки, отправка текста и одобренных шаблонов eDna.
- CRM и WhatsApp доступны из меню Workspace и каталога приложений.

## Подключение

Запросы идут через Workspace `/api/v1/growy/api/` с текущей сессией Workspace. Backend определяет пользователя и организацию, получает сессию Growy и проверяет доступ сотрудника. Frontend не передаёт произвольный tenant и не хранит сервисные ключи. Учебный модуль `/growy/api/` использует свой существующий маршрут.

Внешние аккаунты используют универсальные поля CRM. Создание сделки не вызывает создание ученика, абонемента или оплаты. Возможность открыть модуль определяется ответом `/context/`; сервер остаётся источником прав доступа.

Для проверки доступа Growy должен иметь HTTPS-доступ к `/api/internal/growy/access-check` Workspace. Точный маршрут nginx на сервере Workspace должен сохраняться при последующих развёртываниях.

## WhatsApp

Канал настраивается для организации в Growy. При отключённом канале показывается уведомление, отправка заблокирована. Текст доступен только в открытом окне переписки; для eDna вне окна можно выбрать одобренный шаблон и заполнить переменные. Диалоги обновляются каждые 15 секунд, открытая переписка — каждые 10 секунд. Обновление в скрытой вкладке приостанавливается.

## Роли Growy по должностям

В «Люди → Структура → Роли Growy» владелец компании или платформенный администратор назначает активным должностям одну или несколько ролей: ученик (`employee`), преподаватель (`tenant_admin`), руководитель (`manager`), выдающий сертификаты (`issuer`). Назначения принадлежат компании; одинаковые должности в разных компаниях настраиваются независимо. Для платформенного администратора то же окно доступно в структуре выбранной компании.

Workspace хранит `growy_roles`, передаёт список в подписанном билете входа и возвращает его в проверке доступа. `growy_role` сохраняется как первая роль для совместимости с прежними клиентами. Без настройки используется `employee`; владелец сохраняет `tenant_admin` и получает дополнительные роли своей должности.

После входа из Workspace сотрудник выбирает кабинет в переключателе Growy. Активная роль привязана к JWT, проверяется по членству в текущей компании и сохраняется при обновлении токена. Назначения обновляются при следующем входе из Workspace. Права неназначенных ролей, включая `superuser`, через этот механизм получить нельзя.

Для выпуска применяются миграции Workspace `20261005000000_growy_position_multiple_roles.sql` и Growy `0101_tenantmembership_roles`. Сначала обновляются схема и backend Growy, затем схема и backend Workspace, затем frontend обоих приложений. Обновление схемы Workspace необходимо согласовать с переключением на новый backend, который записывает оба поля роли. Старые одиночные назначения сохраняются.

## Проверка перед публикацией

1. Собрать frontend: `npm run build`.
2. Войти аккаунтом организации, открыть CRM и проверить списки, поиск и формы.
3. Проверить создание и редактирование согласованных тестовых записей, переход из лида или контакта к переписке.
4. Для подключённого тестового WhatsApp-канала проверить входящие сообщения, отправку текста, шаблоны и статусы.
5. Проверить отказ доступа для сотрудника другой организации и после отзыва доступа в Workspace.

Сборка и lint новых файлов проверены локально. Проверка интерфейса с реальной сессией пока не завершена: вход через локальный proxy вернул сообщение о временной недоступности сервера. Это не подтверждает работоспособность отправки сообщений; требуется подключённый канал и согласованный получатель.
