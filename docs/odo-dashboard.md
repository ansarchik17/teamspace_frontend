# Карточки ЭДО на главной Workspace

Переходы в ЭДО используют `/web/eps?section=...`, существующий одноразовый handoff и текущий origin компании. Разрешены только известные разделы; произвольный адрес из query не принимается. Карточка «Заявки» сохраняет существующий запуск SenimDesk и не запрашивает входящие ЭДО. Её отдельный счётчик получает `count` из Workspace `/api/v1/organizations/current/sd-ticket-count`: новые заявки `open_count`, доступные этому пользователю по правилам SD. Бэкенд получает read-only токен связанного пользователя, а в браузер возвращает только число. Обновление раз в 30 секунд, при фокусе и возвращении во вкладку; ошибки SD не блокируют ЭДО. Требуется обновить Workspace backend с этим endpoint; новых переменных и миграций нет.

| Карточка | Раздел ЭДО | Фильтр счётчика |
|---|---|---|
| Согласования | `/odo/approvals` | `status=on_approval` |
| Документы на подпись | `/odo/signings` | `status=waiting_for_signature` |

Счётчики согласований и подписания показывают ожидающие документы, без завершённых согласований и уже подписанных документов. Учитываются документы, доступные пользователю по правилам ЭДО; счётчик не расширяет доступ и не меняет роли директора/администратора.

Источник каждого счётчика — `pagination.total` существующего `GET /odo/api/v1/documents?page=1&limit=1&<filter>`. Количество элементов страницы не используется как общее количество. Перед запросами проверяется активный доступ к модулю через Workspace `/api/v1/organizations/current/access?application=odo`.

Запросы идут на текущем origin с текущим пользовательским Workspace Bearer token. Сервисного секрета в браузере нет. Используются существующие nginx-прокси `/odo/` и доверие токенам Workspace на стороне auth-service ЭДО. Cookie другой сессии ЭДО не подставляются; redirect с токеном запрещён. Ошибка авторизации ЭДО не завершает сессию Workspace.

Ноль показывается только при корректном числовом total=0. При загрузке отображается «—» с текстом загрузки; при 403 — отсутствие доступа; при ошибке сети/API или некорректном ответе — отсутствие данных. Каждая карточка обрабатывает сбой независимо. Значения обновляются каждые 30 секунд в видимой вкладке, при фокусе окна и возвращении во вкладку. Запросы ограничены 15 секундами, отменяются при уходе со страницы; результаты прежней сессии не применяются. При logout значения очищаются.

Для карточек ЭДО достаточно деплоя Workspace front: используются существующие API и прокси. Для счётчика заявок также нужен деплой Workspace backend с новым `/api/v1/organizations/current/sd-ticket-count`. Новых миграций и переменных окружения не требуется. Для приёмки на сервере сравнить ожидающие согласования/подписи с реестрами ЭДО под тем же сотрудником; повторить для другой компании и проверить отказ доступа. Счётчик заявок сравнить с новыми заявками SD под тем же пользователем; проверить, что клик открывает SenimDesk.

Локальные проверки:

```sh
node scripts/test-odo-navigation.cjs
node scripts/test-odo-dashboard-counts.cjs
node scripts/test-sd-dashboard-count.cjs
node scripts/test-odo-assignments.cjs
npm run i18n:check
npm run build
```
